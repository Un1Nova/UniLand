# Передача файлов актуального клиента TechnoMagic RPG

Этот скрипт собирает входные файлы для исследования рецептов. Это **ещё не экспорт рецептов** и не подтверждение их полноты. Скрипт работает локально, не входит в аккаунт и ничего не отправляет в интернет.

## Windows: три шага

1. В официальном лаунчере обнови **TechnoMagic RPG**, зайди на нужный сервер и дождись загрузки. После этого закрой игру. Это даёт клиенту возможность получить серверные данные; успешную синхронизацию рецептов ещё потребуется проверить по самим файлам.
2. Сохрани `Collect-TmrClient.ps1` в папку **Загрузки**. Нажми **Win + R**, вставь следующую команду и нажми Enter:

   ```text
   powershell.exe -NoExit -NoProfile -ExecutionPolicy Bypass -File "%USERPROFILE%\Downloads\Collect-TmrClient.ps1"
   ```

   Скрипт покажет найденные папки клиентов. Введи номер папки **TechnoMagic RPG**, затем проверь размер выбранных файлов и ответь **ДА** на вопрос о создании архива. Если нужной папки нет в списке, вставь полный путь именно к папке клиента, внутри которой есть `mods`. Пустой ответ на вопрос об архиве создаёт только опись.
3. Из созданной папки в **Документах** прикрепи в чат **все** `tmr-inputs-part*.zip` и `inventory.json`. Размер каждой части — не больше **350 МиБ**. Путь к папке будет показан в окне.

Параметр `-ExecutionPolicy Bypass` действует только на запущенный процесс PowerShell и не меняет постоянную политику Windows. Скрипт не требует прав администратора. Если корпоративная политика запрещает запуск PowerShell, не меняй её: сообщи об ограничении.

## Что выбирается

| Источник | Включённые файлы |
| --- | --- |
| `mods` | JAR-файлы, включая вложенные папки; внутри модов уже находятся оригинальные текстуры и переводы |
| Папка клиента | Только `client.jar` и файлы `scripts*.dat` |
| `scripts` | Файлы ZenScript `.zs` |
| `config` | `scripts*.dat`, `.zs` и текстовые настройки с названиями, относящимися к рецептам, крафтам, OreDictionary, Index/LuminousUI или tweaker-модам |
| `assets` и `resources/assets` | Только настоящие PNG в `textures`, их `.png.mcmeta` и `.lang` в `lang` |

Файлы аккаунтов и лаунчера, `storage.txt`, `launcher-data`, пароли, сессии, логи, сохранения, скриншоты и `servers.dat` не включаются. Скрипт не читает `storage.txt` для поиска нестандартного пути клиента: такой путь нужно указать самостоятельно. Символические ссылки и junction-папки не обходятся. Отобранные текстовые настройки и скрипты дополнительно проверяются на поля с паролями/токенами; подозрительный файл пропускается целиком, без сохранения найденного значения. Это узкий сборщик входных файлов, а не универсальный поиск любых персональных данных внутри произвольных модифицированных JAR.

Исходные файлы игры не изменяются. Для каждого выбранного файла опись содержит относительный путь, размер, SHA-256 и время изменения. `collectedAt` означает время сбора, а `lastWriteUtc` — время изменения файла. **Ни одно из них не выдаётся за дату экспорта актуальных серверных рецептов.**

## Дополнительные варианты запуска

Без вопросов и без ZIP, только опись:

```powershell
.\Collect-TmrClient.ps1 -ClientPath 'D:\LoliLand\game-resources\clients\CLIENT\BRANCH' -NonInteractive
```

С явным разрешением на ZIP:

```powershell
.\Collect-TmrClient.ps1 -ClientPath 'D:\LoliLand\game-resources\clients\CLIENT\BRANCH' -CreateZip -NonInteractive
```

Для нестандартного каталога `clients`, но с интерактивным выбором клиента:

```powershell
.\Collect-TmrClient.ps1 -ClientsRoot 'D:\LoliLand\game-resources\clients'
```

`-OutputDirectory` задаёт **новую** выходную папку; существующая папка не перезаписывается. `-MaxPartMiB` задаёт предел размера каждой ZIP-части. В обычном случае каждый исходный файл помещается в одну часть. Отдельный JAR больше лимита делится на куски; расположение, смещения и контрольные суммы указаны в `part-manifest.json` внутри каждой ZIP-части. Нужно передать все части, не распаковывая их вручную.

## Проверка реализации

Скрипт исполнен на официальном portable **PowerShell 7.6.9 для Linux**. Проверка на синтетическом клиенте охватывает исключение credential-canary в обычном и UTF-16 тексте, запрет переходов по ссылкам, стандартный поиск папок, необходимость явного выбора, отсутствие ZIP до согласия, ограничение размера частей, полное восстановление большого JAR и совпадение SHA-256. Реальное исполнение на Windows PowerShell 5.1 ещё не проверено; используемые команды и API рассчитаны на 5.1 и выше.

Исследованный официальный launcher хранит клиенты по схеме `game-resources/clients/<systemName>/<branch>`. Реальные `systemName` и `branch` текущего TMR не получены из API, поэтому скрипт **не выбирает профиль автоматически** по похожему названию.
